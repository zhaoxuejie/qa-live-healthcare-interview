## 1. 背景与目标

### 1.1 背景

- 现状：`web/qa-web/src/views/Consultation.vue` 使用「姓名 + 生日」验证患者身份，首次输入自动创建患者，**没有任何凭证**，任何人输入相同姓名生日即可冒充。
- 痛点：无法识别"同一患者"，也无法为后续问诊记录、消息通知提供可信身份；面试需求明确要求"用户名密码登录方式"。
- 触发原因：README 需求列表第 3 条。

### 1.2 目标

- 业务目标：问诊用户拥有可复用、可验证的账号体系。
- 用户目标：患者可注册账号并登录，刷新/重开页面后仍保持登录，可主动退出。
- 成功指标：
  1. 登录接口成功率 ≥ 99%（成功次数 / 总请求次数，测试环境连续 3 轮测试）。
  2. 登录接口 P95 ≤ 500ms（本地 Docker MySQL，10 并发 curl）。
  3. 数据库中明文密码数量 = **0**（`SELECT COUNT(*) FROM patient WHERE password_hash NOT LIKE '$2%'`）。
  4. 登录态在刷新后保持率 = 100%（同一浏览器会话，token 未过期）。

## 3. 角色与场景

| 角色 | 描述 | 关键诉求 |
|---|---|---|
| 患者（未登录） | 首次使用问诊功能 | 快速注册并进入问诊 |
| 患者（已登录） | 已有账号 | 直接登录，刷新后不掉线 |
| 医生 | 使用医生登录/诊室 | 不受患者登录改造影响 |
| 开发者/测试 | 联调与验收 | 接口契约稳定、错误可预期 |

### 3.1 核心场景

1. 患者打开 `/consultation` → 看到「登录 / 注册」表单。
2. 患者切换到「注册」，填写用户名、密码、姓名 → 注册成功自动登录 → 看到「<姓名> 的问诊」。
3. 已注册患者打开页面 → 输入用户名密码 → 登录成功 → 展示历史问题列表（前端内存数据）。
4. 患者刷新页面 → 前端带 token 调 `/me` → 恢复登录态；token 失效则回到登录表单。
5. 患者点击「退出登录」→ token 失效、前端清理 → 回到表单。

## 5. 功能需求

### FR-01 患者注册

- **优先级**：P0；**对应故事**：US-01
- **描述**：提供 `POST /api/auth/patient/register`，创建患者账号并返回患者信息。
- **业务规则**：
  1. `username`：必填，4–32 位，仅允许字母/数字/下划线/连字符；全局唯一。
  2. `password`：必填，6–64 位；服务端使用 BCrypt（cost=10）存储，禁止明文/可逆加密。
  3. `name`：必填，1–64 位。
  4. `birthday`、`phone` 可选；`gender` 可选。
  5. 注册成功返回 201；用户名重复返回 409；参数不合法返回 400。
- **交互要点**：注册成功后自动登录（返回 token），无需二次输入。
- **异常与边界**：用户名大小写敏感按原样存储；密码前后空格不裁剪；并发同名注册由唯一索引兜底（捕获冲突转 409）。
- **依赖**：`patient` 表（已存在，见 8.2）。

### FR-02 患者登录

- **优先级**：P0；**对应故事**：US-02
- **描述**：`POST /api/auth/patient/login`，校验用户名密码，成功后签发不透明 token。
- **业务规则**：
  1. 用户名不存在与密码错误统一返回 **401**，错误文案一致（"用户名或密码错误"），避免账号枚举。
  2. token 为 32 字节随机数（Base64URL 无填充），有效期 **7 天**，存 `patient_token` 表。
  3. 成功返回 200：`{ code:0, data:{ token, patient:{...} } }`；响应与日志均不得包含密码或密码哈希。
- **交互要点**：登录按钮 loading；失败在表单下方展示错误提示。
- **异常与边界**：数据库不可用返回 500 统一错误体；token 生成失败返回 500。
- **依赖**：FR-01、`patient_token` 表。

### FR-03 登录态校验（/me）

- **优先级**：P0；**对应故事**：US-03
- **描述**：`GET /api/auth/patient/me`，请求头 `Authorization: Bearer <token>`。
- **业务规则**：
  1. token 有效且未过期 → 200 返回患者信息。
  2. 缺失/格式错误/不存在/已过期 → 401。
  3. 过期 token 可被清理（惰性删除即可）。
- **交互要点**：前端启动时调用；失败则静默回到未登录态，不弹错误弹窗。
- **异常与边界**：并发请求不重复创建 token。

### FR-04 退出登录

- **优先级**：P0；**对应故事**：US-03
- **描述**：`POST /api/auth/patient/logout`，使当前 token 失效。
- **业务规则**：
  1. 有效 token → 204，服务端删除该 token 记录。
  2. 无效/缺失 token → 仍返回 204（幂等），或 401；本期采用 **204 幂等**，避免前端卡死。
- **交互要点**：前端无论成功与否都清理本地 token 并回到表单。

### FR-05 前端登录/注册改造

- **优先级**：P0；**对应故事**：US-01/02/03
- **描述**：`Consultation.vue` 用「登录 / 注册」Tab 替换原"姓名+生日"验证。
- **业务规则**：
  1. 未登录：显示表单，可切换登录/注册。
  2. 注册字段：用户名、密码、姓名（生日可选，沿用日期选择器）。
  3. 登录成功：展示「<姓名> 的问诊」，沿用现有问题列表/提交问题逻辑。
  4. 刷新：读取 `localStorage.qa_patient_token` → 调 `/me` → 成功则直接进入问诊页。
  5. 退出：清理 token 与 `currentPatient`。
  6. 错误提示：用户名重复、密码错误、网络失败分别给出明确中文提示。
- **异常与边界**：页面不再提供"姓名+生日即可登录"的入口。
- **依赖**：FR-01~FR-04。

### FR-06 演示患者种子数据

- **优先级**：P1；**对应故事**：US-02
- **描述**：`deploy/mysql/init/03_seed_patient.sql` 写入 1 个演示账号。
- **业务规则**：用户名 `demo_patient`，密码 `123456`（仅文档可见），`password_hash` 为 BCrypt；重复初始化幂等。
- **依赖**：FR-01（需要 BCrypt 工具生成哈希）。

## 8. 接口与数据影响

### 8.1 接口清单

| 方法 | 路径 | 用途 | 入参 | 出参（data） | 状态码 |
|---|---|---|---|---|---|
| POST | `/api/auth/patient/register` | 注册 | `{username,password,name,birthday?,phone?}` | `{token, patient}` | 201/400/409/500 |
| POST | `/api/auth/patient/login` | 登录 | `{username,password}` | `{token, patient}` | 200/400/401/500 |
| GET | `/api/auth/patient/me` | 当前用户 | Header `Authorization: Bearer <token>` | `patient` | 200/401/500 |
| POST | `/api/auth/patient/logout` | 登出 | Header `Authorization: Bearer <token>` | `null` | 204/500 |

**统一响应体**：`{"code":0,"message":"ok","data":...}`；失败 `{"code":40000|40100|40900|50000,"message":"...","data":null}`。

**患者对象（响应）**：`id, username, name, birthday, phone, gender`（**绝不包含 password_hash**）。

### 8.2 数据模型影响

| 表 | 变更 | 字段/索引 | 迁移方式 |
|---|---|---|---|
| `patient` | 已存在（T06 建表） | `username UNIQUE`、`password_hash VARCHAR(100)` | 无新增 |
| `patient_token` | 已存在（T06 建表） | `token PK`、`patient_id FK`、`expires_at` | 无新增 |
| 种子 | 新增 `03_seed_patient.sql` | `demo_patient` | `docker compose down -v && up -d` |

- 字符集：`utf8mb4` / `utf8mb4_unicode_ci`。
- 回滚：删除种子脚本并 `down -v` 重建即可；不涉及线上迁移。

### 8.3 兼容性与影响面

- 旧"姓名+生日"入口移除，属于**行为变更**，需在测试报告记录。
- 医生登录（`/doctor/login`）不受影响，已使用 `POST /api/doctors/login`。
- 问题数据仍为前端内存，刷新丢失属既有行为，不在本期修复。

## 9. 验收标准

### AC-01 注册成功（FR-01）

- **Given** 用户名 `patient_test_01` 未被注册
- **When** POST `/api/auth/patient/register`，body `{username:"patient_test_01",password:"123456",name:"测试患者"}`
- **Then** HTTP 201，`code=0`，返回 `token` 与 `patient`，`patient.username=patient_test_01`，响应不含 `password_hash`

### AC-02 重复用户名（FR-01）

- **Given** AC-01 已注册 `patient_test_01`
- **When** 再次提交相同用户名
- **Then** HTTP 409，`code=40900`，提示"用户名已存在"

### AC-03 弱密码（FR-01）

- **Given** 任意未注册用户名
- **When** `password` 长度为 5
- **Then** HTTP 400，`code=40000`，不创建账号

### AC-04 登录成功（FR-02）

- **Given** `demo_patient / 123456` 已存在
- **When** POST `/api/auth/patient/login`
- **Then** HTTP 200，`code=0`，返回 `token`（长度 ≥ 32），`patient.name` 正确，无密码字段

### AC-05 密码错误（FR-02）

- **Given** `demo_patient`
- **When** 密码为 `wrong`
- **Then** HTTP 401，`code=40100`，文案"用户名或密码错误"

### AC-06 不存在用户（FR-02）

- **Given** 用户名不存在
- **When** 登录
- **Then** HTTP 401，且文案与 AC-05 **完全一致**（防枚举）

### AC-07 会话校验（FR-03）

- **Given** AC-04 获得的 token
- **When** 带 `Authorization: Bearer <token>` 请求 `/me`
- **Then** HTTP 200，返回同一患者；不带 token 或伪造 token → 401

### AC-08 登出（FR-04）

- **Given** 已登录 token
- **When** POST `/logout` 后再用同一 token 请求 `/me`
- **Then** logout 返回 204；`/me` 返回 401

### AC-09 前端登录态持久化（FR-05）

- **Given** 浏览器已登录并写入 `localStorage.qa_patient_token`
- **When** 刷新 `/consultation`
- **Then** 直接显示「<姓名> 的问诊」，无表单闪烁（允许 loading 态）

### AC-10 前端错误提示（FR-05）

- **Given** 未登录
- **When** 输入错误密码 / 重复用户名
- **Then** 表单下方出现明确中文错误，不白屏、不跳页

### AC-11 旧入口移除（FR-05）

- **Given** 源码
- **When** `rg "生日" web/qa-web/src/views/Consultation.vue`
- **Then** 无"姓名+生日即可登录"的验证入口（生日可作为注册可选字段保留）

### AC-12 构建与数据安全

- **Given** 全部改动完成
- **When** `npm run build`；`SELECT COUNT(*) FROM patient WHERE password_hash NOT LIKE '$2%'`
- **Then** 构建 exit 0；明文密码计数 = 0
