## 1. 需求理解与项目分析

- **阶段**：任务启动
- **目的**：在不改动代码的前提下，弄清项目用途、技术栈、目录结构、启动链路与二次开发关键文件。
- **提示词（整理稿）**：

```text
请整体分析这个本地项目，不要修改代码。说明：
1) 项目用途与技术栈；
2) 目录/模块划分；
3) 启动流程与入口文件；
4) 二次开发应优先看的文件；
5) 运行依赖。
不确定的内容如实说明，不要脑补。
```

- **执行要点**：只读浏览 `README.md`、`web/qa-web`、`server/`、`docker-compose.yml`；标注不确定项。
- **产出**：项目分析结论（技术栈、启动链路、关键文件清单）。
- **关键决策**：
  - 本轮**只分析不改代码**；
  - 对无法确认的内容明确标注"不确定"，不做推测性断言（用户原话："不确定的内容如实说明，不要脑补"）。

## 2. 环境依赖安装（Windows）

- **阶段**：环境准备
- **目的**：安装缺失依赖，保证前端能构建、后端能编译。
- **提示词（整理稿）**：

```text
帮我安装缺失的依赖（Windows）：
- 前端 npm 依赖；
- JDK 17+ 并配置 JAVA_HOME。
优先使用国内镜像；给出安装步骤，每一步都带验证命令。
不要动 Docker、不要启动服务；遇到权限或版本冲突就停下来向我报告。
```

- **执行要点**：`npm install`；配置 `JAVA_HOME`/`PATH`；Maven 使用 `D:\dev\maven-settings.xml`（Aliyun 镜像）。
- **产出**：前端依赖安装完成；JDK 17 可用；依赖版本验证命令与结果。
- **关键决策**：
  - 使用阿里云 Maven 镜像，避免外网阻塞；
  - **不启动 Docker/服务**（遵守用户边界）；
  - 每次 pwsh 调用显式设置 `JAVA_HOME`（harness 环境变量不跨调用）。

## 8. 数据库与医生 API（需求 2）

- **阶段**：T05–T09
- **目的**：MySQL 管理医生数据，后端提供列表 API，前端联调并证明"改库即变"。
- **提示词（整理稿）**：

```text
继续。按计划实现需求 2：
- 用 docker compose 起 MySQL 和 phpMyAdmin；
- 把医生 JSON 迁到数据库；
- qa-service-user 提供医生列表 API（不返回密码）；
- 前端医生页改为调 API，并用改库刷新验证数据确实来自 MySQL。
```

- **执行要点**：
  - `docker-compose.yml`（mysql:8.0 + phpmyadmin:5 + healthcheck + init 挂载）；
  - `01_schema.sql`、`02_seed_doctors.sql`（5 位医生，utf8mb4）；
  - JPA：`Doctor`、`SpecialtiesJsonConverter`、`DoctorDto`（无 password）、`/api/doctors`；
  - 前端 `api/http.ts`、`api/doctors.ts`、store `loadDoctors()`、错误重试；
  - T09 改库 → 刷新页面 → 改回。
- **产出**：`docker-compose.yml`、`deploy/mysql/init/*`、医生 API、前端联调、T09 证据。
- **关键决策**：
  - MySQL 用 **8.0**（8.4 镜像拉取在此网络下卡住）；
  - `SET NAMES utf8mb4` 修复中文双重编码；
  - `ddl-auto=none`（表结构由 init SQL 管理）；
  - 医生登录改走 `POST /api/doctors/login`，避免删 JSON 后密码校验失效。
