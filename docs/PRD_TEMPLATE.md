# PRD 文档模板

> 用途：本模板用于把「一个特性」从想法推进到可验收、可拆分、可执行的规格说明。
> 使用方式：复制本文件为 `docs/PRD-<特性名>.md`，删除提示性斜体文字后按章节填写。
> 质量原则：**每个功能需求都必须有可测量的验收标准；范围必须写清"不做什么"；拆分步骤必须能直接排期。**

- 现状：`<当前系统/流程是什么样，存在什么问题>`

### 1.2 目标（做成什么样）

- 业务目标：`<可衡量的业务结果>`
- 用户目标：`<用户完成任务后获得什么>`
- 成功指标：`<指标名 + 目标值 + 统计口径 + 观察周期>`
  - 示例：`登录成功率 ≥ 99%（登录成功次数/登录请求次数，上线后 7 天）`

> 规则：成功指标必须是**可测量**的（有分子分母、阈值、时间窗），不接受"体验更好""更流畅"。

## 13. 模板质量门禁（提交 PRD 前自检）

- [ ] 背景、目标、成功指标齐全，且指标可测量
- [ ] In Scope / Out of Scope 明确，Out of Scope 至少 3 条
- [ ] 每条 FR 有优先级、业务规则、异常边界
- [ ] 每条 FR 至少对应 1 条 Given/When/Then 验收
- [ ] 验收标准覆盖正向、负向、边界
- [ ] 接口清单含方法、路径、入参、出参、错误码
- [ ] 数据模型影响明确（或声明"无数据变更"）
- [ ] 拆分步骤可执行、有依赖顺序、有改动文件
- [ ] 风险与待确认项有负责人和结论
